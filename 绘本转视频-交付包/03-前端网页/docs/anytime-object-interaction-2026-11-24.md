# 任意播放时刻的对象互动（2026-11-24）

## 行为与修复

用户要求在视频任意时刻点击目标都能开始互动。本轮把点选入口从原书页码映射中解耦：稳定片段、转场和片尾均可将实际暂停帧提交给互动视觉服务。未映射时 `interaction_page`、对象助手 `page_number` 为 `null`，不把邻近原书页冒充当前页。

- 主对话仍在回答时，点选会中断其前端接收和播报，打开独立对象助手；保持主对话记录隔离。已经受理的外部调用不保证能够撤回。
- 连续点选以最新目标为准；旧识别、背景和问答结果不能覆盖新窗口。等待媒体解码或停止麦克风时同样校验请求版本。
- 截图与时间点在同次点选中固定。首次载入或跳转时最多等待 3 秒，解码完成后按实际画面矩形重新计算坐标，避免竖屏视频留白误命中。后续跳转、恢复播放或切书会使等待中的旧点选失效。
- 没有页码的助手仅显示时间点。实际帧问答可以引用 `frame_evidence`，包含 `source: actual_video_frame`、`time`、`image_url`；对象窗口可展开查看该帧。空页码列表仅在实际帧存在、视觉复核通过且作用域为 `current_frame` 时允许。
- 原书背景仍要求原书页证据。转场附近的页面仅作为检索候选，由模型比较原图后引用；后台不据时间强制指定页码。背景版本更新为 `object-background-source-visual-v5`，旧缓存不继续复用。
- 画面动作与故事关联分别生成和复核。无当前页时，动作依据使用时间点，故事关联仍使用原书页码。

接口中的 `evidence` 继续表示原书页列表；`frame_evidence` 是可选的实际帧证据。不能将空页码列表与“未做任何证据核对”混为一谈。模型提供的无据原书事实仍被拒绝。

## 验证记录

环境：macOS Apple Silicon、Python 3.12、本机工作台、Chrome 无头浏览器，沿用已配置的互动视觉和百炼语音服务。开发自拟点选和问题，不使用赛事隐藏问题或答案。

1. 自动回归覆盖转场/片尾、空白拒识、无页码追问、原书背景、两路证据复核、主对话忙、连续点选、首帧加载、横竖比例、旧请求失效、恢复播放及证据展示。完整 `python -m pytest -q`：451 项通过、0 失败、0 跳过，6 条已知依赖弃用警告；两个 JavaScript 文件语法和依赖一致性检查通过。
2. 既有授权成片抽取 5 个实际帧：8、14.4、64、157、168 秒，分别点选可见的人物、动物或物品；5 次返回识别，服务端耗时 6.45–8.34 秒。本组关闭 TTS，使用本地提取帧，不能代表真实用户端到端延迟或全帧准确率。
3. 14.4 秒转场独立服务测试返回原书背景及两页证据，耗时 14.95 秒；同对象一次衣着追问通过实际帧复核，`evidence_pages=[]`，返回该时间点截图依据。未执行剩余 9 页批量理解。
4. Chrome 中 14.4 秒叠化帧识别成功，但该次背景未确认，界面保留助手和重试入口。较清晰的 15 秒转场实测：识别人物、背景引原书第 2 页、配音完成，合计 31.60 秒。用模拟的主对话等待状态验证点选中断；识别、背景及 TTS 使用真实服务。主对话记录不变、输入控件可用、无页面脚本错误。
5. Chrome 播放中点选、连续新旧请求交错另用受控模拟响应检查通过，不计作模型质量测试。真实服务结果、截图与原始输出仅在忽略目录 `artifacts/anytime-click-20261124/` 保存。

## 边界

“任意时刻可以发起点选”不等于“每个像素都能确认对象和故事背景”。纯背景、空白、叠化严重、模糊遮挡和无对应原书内容的元素仍可返回未确认。现有生成与独立复核使用同一视觉模型，可能共享识别偏差；本轮样本不足以量化全片准确率、P50/P95 或赛事成绩。

仍需第二本授权书的完整导入与交互验证，以及更大范围的真实触控测试。没有新 API 配置项，也未重新生成视频或配音旁白。
